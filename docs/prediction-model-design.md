# 预测模型设计

## 1. 评分目标

预测模型模块对应课程评分中智能预测部分。目标不是只画一条曲线，而是完整回答：

- 使用了哪些数据；
- 为什么选择这些模型；
- 如何划分训练集和测试集；
- 各模型的 MAE、RMSE、R2 表现如何；
- 模型如何部署到平台；
- 预测结果如何参与告警或自动控制。

为了保证 100 分，平台至少实现三种模型，并在页面中展示不同模型结果与分析。

## 2. 预测任务

### 2.1 主要任务

| 任务 | 输入 | 输出 | 用途 |
| --- | --- | --- | --- |
| 单节点温度预测 | 节点历史温度、湿度、光照、时间特征 | 未来 10/15 分钟温度 | 高温预警、风扇控制 |
| 单节点湿度预测 | 节点历史湿度、温度、光照、时间特征 | 未来 10/15 分钟湿度 | 高湿预警 |
| 区域平均温度预测 | 多节点温度、区域、人员状态 | 未来区域平均温度 | 区域环境管理 |

首版主交付选择“单节点温度预测”和“单节点湿度预测”。多区域预测作为增强项。

### 2.2 数据来源

| 来源 | 说明 | 用途 |
| --- | --- | --- |
| ESP32-S3 实时采集 | DHT11 温湿度、光照与空气质量节点 | 主要在线数据与少量训练数据 |
| CC2530 可选支线 | DHT11 温湿度或光照节点 | 固件与协议兼容性测试 |
| Gateway 离线 JSONL | MQTT 断线时缓存 | 回放和鲁棒性测试 |
| 串口模拟器 | 按真实协议生成数据 | 补足开发阶段数据 |
| 历史数据库 | PostgreSQL `sensor_readings` | 训练、验证和测试 |

所有训练数据必须记录采集时间、节点 ID、指标名和来源。模拟数据必须在报告中标注，不与真实数据混淆。

## 3. 特征工程

### 3.1 原始特征

- `temperature`
- `humidity`
- `light`
- `node_id`
- `area`
- `captured_at`
- `people_count`
- `scene_label`
- `lamp_state`
- `fan_state`

### 3.2 时间特征

- `hour`
- `minute_of_day`
- `day_of_week`
- `is_opening_hours`

### 3.3 滞后与窗口特征

对每个 `(node_id, metric)` 单独计算：

- `lag_1`
- `lag_3`
- `lag_5`
- `rolling_mean_5`
- `rolling_mean_15`
- `rolling_std_15`
- `delta_1`
- `delta_5`

采样间隔若不稳定，训练前需要按固定周期重采样，例如 30 秒或 60 秒。

## 4. 模型选择

### 4.1 必选模型

| 模型 | 作用 | 选择理由 |
| --- | --- | --- |
| Persistence Baseline | 预测值等于最近观测值 | 给所有模型提供最低基线，避免只展示复杂模型 |
| Linear Regression / Ridge | 线性回归 | 可解释性强，适合说明特征影响 |
| Random Forest Regressor | 非线性树模型 | 对小数据和非线性关系较稳 |
| HistGradientBoostingRegressor | 梯度提升树 | 作为更强的传统机器学习模型 |

课程展示至少使用其中三种。推荐四种全展示。

### 4.2 可选增强模型

| 模型 | 用途 | 风险 |
| --- | --- | --- |
| LightGBM/XGBoost | 更强表格模型 | 额外依赖，部署复杂度增加 |
| Tiny MLP | 展示深度学习 | 小数据下可能不稳定 |
| Prophet | 时间序列趋势 | 适合周期性数据，但短期课设数据可能不充分 |

## 5. 训练与验证流程

### 5.1 数据切分

时间序列不能随机打乱。推荐：

```text
前 70% 时间段 -> train
中间 15% 时间段 -> validation
最后 15% 时间段 -> test
```

如果数据量较少，可以使用滚动窗口验证：

```text
train: [t0, t1] -> test: [t1, t2]
train: [t0, t2] -> test: [t2, t3]
train: [t0, t3] -> test: [t3, t4]
```

### 5.2 评价指标

| 指标 | 说明 |
| --- | --- |
| MAE | 平均绝对误差，最直观 |
| RMSE | 对大误差更敏感 |
| R2 | 拟合解释能力，小数据时需谨慎解释 |
| Inference latency | 单次预测延迟 |
| Model size | 模型文件大小 |

### 5.3 产物

每次训练保存：

- 训练配置 JSON；
- 数据时间范围；
- 特征列表；
- 模型文件；
- 测试集预测 CSV；
- 指标 JSON；
- 预测对比图；
- 误差分布图。

文件保存到 S3-compatible 对象存储，PostgreSQL `prediction_runs` 和 `object_artifacts` 保存引用。

## 6. 推理与平台集成

### 6.1 后端接口

后端提供：

- `POST /api/prediction/runs`：启动训练或评估。
- `GET /api/prediction/runs`：查看历史运行。
- `GET /api/prediction/latest`：获取最新预测结果。
- `GET /api/prediction/metrics`：获取模型对比指标。

### 6.2 在线预测

在线预测由后端定时任务触发：

1. 从 PostgreSQL 拉取最近窗口数据。
2. 生成特征。
3. 调用当前激活模型。
4. 写入 `predictions`。
5. 若预测超过阈值，创建告警或控制命令。

### 6.3 自动控制规则

示例：

```text
IF predicted_temperature_15m > 30
AND people_count > 0
AND fan_state != on
THEN create control command: fan on
```

```text
IF predicted_humidity_15m > 75
AND scene_label != vacant
THEN create alert: high humidity risk
```

## 7. 页面设计

预测页面需要展示：

- 节点和指标选择；
- 时间范围选择；
- 实际值与预测值曲线；
- 多模型指标表；
- 当前推荐模型；
- 特征重要性；
- 训练数据时间范围；
- 误差样例；
- 模型文件和报告下载链接。

## 8. 答辩证据清单

| 证据 | 说明 |
| --- | --- |
| 数据集说明 | 节点、时间范围、采样间隔、缺失处理 |
| 模型选择说明 | 为什么选 baseline、线性模型、树模型 |
| 实验指标表 | MAE、RMSE、R2、延迟 |
| 曲线图 | 实际值 vs 预测值 |
| 误差分析 | 哪些时段预测差，为什么 |
| 部署截图 | Web 页面实时预测 |
| 控制联动 | 预测触发告警或风扇控制 |

## 9. 不应夸大的点

- DHT11 精度有限，不能声称达到工业级预测精度。
- 短周期课程采集数据不能声称模型具备长期泛化能力。
- 模拟数据可以用于开发和演示，但报告中必须标明来源。
- 如果 R2 较低，应解释为数据量、传感器噪声或场景变化导致，而不是隐藏结果。
